# 多次撤销

2026-09-18。设置 → “多次撤销”，仅 macOS 行内输入法模式显示，默认关闭，重启后保留设置。关闭时仍按现有规则撤销当前句；开启后，连续撤销手势可以逐步回退同一输入框里的听写和编辑。开关不改变默认听写、右滑结束本句并转编辑、模型结果返回后直接应用的流程。

## 撤销顺序和范围

例如：听写 A → 口述编辑指令 B 并应用 → 听写 C。连续撤销依次为：

1. 移除听写 C。
2. 撤销 B 的编辑结果，恢复为编辑前原文＋听写指令 B。
3. 移除听写指令 B。
4. 移除听写 A。

正在听写时先取消当前句；正在等待模型时先结束编辑并恢复听写，迟到的 ASR／模型结果不能再次写入。空句不隔断已有历史。撤销后重新开始听写会建立新的操作分支；本功能不提供重做。

历史仅在本次持续使用同一输入框期间有效。手动输入、鼠标接管／移动光标、切换输入框、切换输入法、断开输入法连接、无法确认撤销结果时会清空历史，避免随后删除不再归属本次操作的文字。关闭开关会清除较早记录，再开启不会恢复它们。

最多保存 100 条较早操作，加上当前句。历史文本合计受 4,194,304 个 UTF-16 单元的预算约束，约合 8 MiB 的 UTF-16 文本；超过预算时淘汰最早记录，单条超预算则清空较早历史，保留现有当前句撤销能力。这不是进程实际内存上限：Swift 字符串共享、对象开销和当前会话原有快照会影响实际占用。

未定稿听写直接清除本句组合。微信和 Codex 的定稿听写先向前选中本句，经范围核对后发送一次 Backspace，不全选、不复制。已应用编辑需要恢复原文，无法只靠 Backspace；微信沿用已验证的全文选区兼容替换，Codex 和其他应用沿用 IME 范围替换。所有路径保留目标、句 ID、版本和结果确认。

Codex 编辑结果及历史编辑恢复均直接替换已确认的原文范围，不把结果重新建立为输入组合。按用户后续确定的方式，文字回读匹配后直接发送一次 Cmd+Down 到全文末尾，不要求光标还在写入前的位置。撤销编辑则恢复到原听写句末，保证下一次撤销能正确移除指令句。由于 Codex 可能暂时回报旧光标，定位后按实际回读进行少量左／右方向键纠偏；读数不变时不重复发送同一移动，最多四次且沿用原超时上限。不全选、不复制、不再次写入文字；每一步保留文本、前台目标、输入框和事务校验。

## 实现与延迟

原生 `CompositionUndoHistory` 保存历史。听写记录只保存本句、插入位置及被替换选中文字；编辑记录还保存用于恢复的原文和结果。新的起句复用原有快照，流式 partial 不扫描撤销栈、不增加客户端读取；不新增 ASR 或 LLM 请求。

主机保存历史句 ID 与录音会话的映射。撤销旧句更新原来的记录，不误写入最新录音记录。恢复旧记录会生成新的事务版本，旧请求不能再次应用。

性能实验使用生产 `CompositionSession`／`CompositionUndoHistory` 和内存模拟客户端，连续听写 120 句，再测连续编辑。以下是 10 万字原文的单次调用中位耗时，单位毫秒：

| 阶段 | 关闭 | 开启 | 差值 |
| --- | ---: | ---: | ---: |
| 起句 | 0.0121 | 0.0136 | +0.0015 |
| 流式更新 | 0.0419 | 0.0412 | -0.0007 |
| 定稿 | 11.8570 | 11.8337 | -0.0233 |
| 编辑结果应用 | 60.7510 | 61.3870 | +0.6360 |

细小正负差异不能当作稳定收益或退化。这次实验没有发现栈开启后起句、partial、定稿的明显额外耗时；较长编辑记录的保存增加少量处理。120 句的客户端读取次数开关两组均为 960 次。原本对长文本做快照／核验的成本仍然存在，不能据此声称任意长度输入框都没有延迟。

历史额外保留的文本量：连续听写样本为 828 个 UTF-16 单元；10 次 10 万字编辑后为 2,000,181 个单元，约 3.8 MiB 的 UTF-16 文本。内存是主要新增成本。执行实际撤销时的耗时仍取决于要删除的句长、恢复的原文范围和目标应用响应，不能由内存模拟成绩推断。

上述数字不包含戒指、网络 ASR、模型、真实应用跨进程读写和屏幕绘制时间，不是端到端 tap 延迟。上一句收尾期间下一次 tap 的启动门控没有在本次修改。原始数据见 [performance.json](../experiments/ime_undo_history_20260918/performance.json)。可执行 `.build/input-method/undo-history-tests --benchmark` 复测。

## 验证范围

151 项 Swift 测试通过，其中 13 项撤销栈回归覆盖听写／编辑混合回退、关停开关、空句、选区恢复、空编辑结果、同长度外部修改、光标变化、容量预算和迟到结果隔离。28 项生产适配器回归包含实际无窗口 `NSTextView` 的微信／Codex 撤销路径；这些测试不是对真实微信或 Codex 客户端的验收。

81 项 Python 回归通过，覆盖设置持久化、主机状态、历史录音归属、快捷键边界、IPC、安装器和语音主链路；实际 Swift／Python IPC 握手与命令回传通过。真实应用内连续混合撤销仍需使用新版组件进行体验验证。
