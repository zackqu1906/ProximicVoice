# macOS 小型输入法组件迁移方案

日期：2026-09-17。用户已确认手动选择输入法，开发按此方案执行；构建与实际验收状态见 `INLINE_DICTATION.md`。

## 1. 目标与范围

优先让真实 Codex 和微信达到以下完整体验：每句默认听写，ASR 流式文字在原输入框内以原生未定稿文字呈现；光标附近只有状态和必要操作；一句话可以撤销、转换为编辑、取消编辑并恢复听写。

macOS 此功能经输入法组件读写文字。原 AX 行内写入、剪贴板粘贴、模拟按键写字和透明窗口伪下划线路径已移除。戒指识别、ASR 后端和模型处理继续使用现有主程序。Windows 的独立实现与共享数据类型不因本次迁移而删除。

2026-09-18 用户确认微信例外：本机微信 Qt 5 忽略输入法的替换范围，因此仅 `com.tencent.xinWeChat` 增加原生选区／撤销快捷键兼容层，其他应用保持原生 IMK。用户随后明确时序：等待模型期间保留本句指令；模型返回后先撤除指令，再全选并经 IME 读取、核对全文，将结果合入原先可验证的编辑范围，最后经 IME 替换选区并回读核验。读取无需修改系统剪贴板。普通未定稿撤销直接清除本句组合；微信定稿撤销从仍归属本句的末尾光标向前选中本句，确认精确范围后退格一次，若起句替换过选中文字则用 IME 恢复原选中文字。不全选全文、不复制、不依赖 Cmd+Z 分组。取消编辑继续还原听写，再次撤销只移除该句。权限、目标、事务或选区校验失败即停止，不向其他应用发送快捷键，不发送 Return，不自动选择输入法。

2026-09-18 多次撤销扩展：设置增加默认关闭的“多次撤销”，开启后保存当前输入框内的听写和编辑历史，关闭则保持当前语音事务的撤销方式。编辑仍先恢复听写，再次撤销才移除指令句。Codex 已定稿听写也使用本句选区＋退格兼容路径，不允许 Codex 全选快捷键；其编辑仍经 IMK 替换。具体边界和测试数据见 [多次撤销](UNDO_HISTORY.md)。

结束语音只定稿文字，不触发 Codex 或微信的发送按钮。本轮范围是输入、编辑与撤销，不增加操作智能体确认按钮等功能。

## 2. 已确认的产品行为

| 时机／操作 | 文本行为 | 操作条与状态 |
| --- | --- | --- |
| 开始一句 | 记录当前输入框的句前原文和选区；始终进入听写 | `听写 · 可以说话 · 撤销`；有下划线后出现转换 |
| ASR partial 到达 | 更新本句 marked text；允许 ASR 修订前面的字，不追加重复文本 | 原生下划线，操作条跟随插入位置 |
| 结束手势 | 结束本句音频，等待 ASR final，以 final 定稿 | 下划线消失；`已听写 · 撤销` 短暂保留 |
| 说话中转换为编辑 | 立即结束本句；等 final 后，以这句话为指令编辑句前原文 | `编辑 · 正在收尾`，随后 `正在编辑 · 取消` |
| 已定稿后右滑 | 不再将本句改为编辑；需要开始新句口述指令 | 保持听写，仍可撤销 |
| 等待编辑结果 | 保留带下划线的指令，暂停收取下一句；模型收到句前原文与独立指令 | 旋转加载图标＋`正在编辑… · 取消`；不展示预览确认面板 |
| 模型完成 | 验证目标和原文未被接管，移除指令并恢复句前选中文字，再直接应用编辑结果 | `已编辑 · 还原听写` |
| 等 ASR final 时取消转换 | 本句仍结束，继续接收 final，但不调用编辑模型 | 按普通听写定稿 |
| 模型处理中取消 | 作废本次模型请求，恢复本句听写内容 | 回到已听写 |
| 编辑应用后取消 | 恢复到“原文＋本句听写”的状态 | 回到已听写；之后还可撤销本句 |
| 听写中撤销 | 停止并丢弃本句后续音频、恢复句前状态 | 本次事务结束 |
| 听写定稿后撤销 | 撤销整句；如起句替换过选中文字，恢复被替换的原文 | 本次事务结束 |
| 下一句 | 以当前文本为新的句前原文，重新开始听写 | 不继承编辑模式 |

听写不调用大模型润色，不接自动意图分类，不保留持久的“听写／编辑”模式切换。手势沿用用户当前绑定；“类型转换”在本路径中改为“将本句转换为编辑”。

定稿／应用后操作条默认显示 5 秒；这是沿用当前实现的可调整默认值。隐藏只是收起界面，不自动废弃撤销资格。只要原事务仍有效，撤销手势可以重新显示操作条并执行撤销；转换仅在本句仍有下划线时有效。模型处理中不启动自动隐藏倒计时。

用户手动打字、移动光标、换输入框、主动切换输入法或开始新句时，旧事务结束：尽可能按输入系统的提交回调保留当前可见内容，不强制拉回焦点，不让迟到的 ASR／模型结果继续改字。旧快照不能覆盖用户后续手动输入。

正在组合时的 Enter 先用于结束组合，不把同一次按键继续透传成聊天发送；组合结束后正常按键交回目标应用。Esc／现有取消快捷键只在有本组件事务时执行上述取消语义，空闲时不劫持应用快捷键。

## 3. 组件分工

```mermaid
flowchart LR
    A[戒指音频和现有手势] --> B[Python 主程序\nASR、模型、设置]
    B <-->|本机 IPC：句 ID、状态、文本| C[Swift 输入法组件\n会话、原生组合、撤销、操作条]
    C <-->|macOS 文本输入协议| D[Codex / 微信输入框]
```

### Python 主程序

- 保留设备连接、识别、结束本句通道、模型配置和已有模型调用契约。
- ASR partial／final 和现有手势事件通过 IPC 发给组件，模型仅在组件发出编辑请求后调用。
- 接收组件返回的事务状态、上下文、错误与应用结果；界面展示“未安装／未启用／未选中／已连接”等实际状态。
- 编辑等待期继续暂停新句，完成或取消后恢复；音频线程不等待文本客户端 RPC。
- macOS 不再由 `_capture_desktop_reference()` 或独立 AX context reader 确定输入目标。

### Swift + InputMethodKit 组件

- `IMKServer` 管理客户端连接，`IMKInputController` 管理当前输入会话。
- 在主线程串行调用客户端 API、变更事务和展示原生操作条；不在主线程运行 ASR／LLM。
- partial 使用 `setMarkedText`；final 使用提交接口结束组合，不把所有 partial 都提交成普通文字。
- 通过当前 client 读取原文、选区、marked range 和光标矩形；由组件统一处理 UTF-16 范围及 Unicode 边界。
- 保存句前快照、听写快照、编辑结果以及可撤销范围；主程序不持有可调用的跨进程 client 对象。
- 处理组件失活、系统要求提交、用户接管、目标变化与断连；这些事件统一废弃过期写入权。

### IPC 与并发

首版使用用户私有目录中的 Unix domain socket：Swift 与 Python 均可直接使用，不增加本地 HTTP 服务或端口。目录／套接字限制为当前用户，协议含版本协商和连接凭据，日志不记录 context 正文。

每条操作携带连接 epoch、客户端会话 ID、句 ID、事件序号和编辑 revision。组件每次应用前复核它们；重复 final 不重复提交，取消之后到达的结果只丢弃。积压的 partial 合并为最新内容，结束／取消／final 不能被 partial 合并覆盖。

组件是文字事务状态的唯一权威；主程序负责音频和模型任务。两侧通过确认消息同步，不各自维护互相冲突的听写／编辑状态机。

## 4. context、编辑和撤销

记句前原文为 B，本句 ASR final 为 R，按原选区插入 R 后的听写状态为 D，模型以 B 与 R 为输入生成的结果为 E。

- 普通听写：`B → D`。
- 听写撤销：`D → B`，包括恢复原来被选中的文字。
- 转编辑：本句仍为原生组合时确认，等待 final 后保留带下划线的 R，模型输入为 `B + 指令 R`；模型结果到达并验证事务仍有效后，才撤掉指令、恢复 B，再应用 E。
- 取消编辑：结果尚未应用时，将保留的 R 定稿为 D；已应用时 `E → D`。再次撤销才是 `D → B`。

模型 context 不把本句语音指令混进原文。已有的 ASR 上下文提示也改为来自同一份 IME 句前快照；ASR 提示可以按现有上限截取，但编辑全文快照不能因该上限而被误截断。ASR context 不可用时按后端原有无 context 能力继续识别，不沿用其他输入框的缓存。

能力分开验证：

1. 原生组合：marked text 能显示、更新、提交和在组合阶段撤销。
2. 上下文读取：返回的是完整当前文本框内容、局部范围还是不可用；检查实际范围与 UTF-16 长度，空字符串与读取失败分开处理。
3. 已提交文字替换：客户端是否真正支持指定范围替换，以及结果和选区能否核对。

第 1 项通过不等于第 2、3 项通过。Apple 接口允许范围读取退化、范围替换被忽略，因此全文编辑与定稿后撤销必须单独验收。对尚未验证的客户端不拿真实用户草稿做破坏性探针；先在可丢弃草稿中测试。

先用 `supportsProperty(kTSMDocumentSupportDocumentAccessPropertyTag)` 等公开能力查询，再核对真实读取与替换结果；能力声明本身不代替验收。`length()` 可能昂贵，只在建立／验证快照时按需查询。

若只有局部 context，不把它当成整框原文，也不转回 AX／全选复制。保留客户端返回的实际 UTF-16 范围；可读原文必须覆盖起句选区且通过精确回读校验，编辑与恢复只替换该范围，完成后操作条显示“已编辑可读原文”，`context_complete` 保持 false。无法确认范围则保留听写并提示。定稿后的本句撤销独立校验本句，不绑定到全文能力。对首批目标 Codex／微信，若完整功能未通过，则该应用仍算“未完成兼容验收”，不能以降级听写声称全部完成。

定稿后恢复通过已验证的范围替换和事务快照完成，不能用 `unmarkText` 或一次 `Cmd+Z` 冒充精确撤销。应用前后核对会话、文本、范围；核对失败立即停写，不盲目再覆盖一次。原生客户端不提供跨进程原子 compare-and-swap；并发手动接管仍是需要真实验证的边界。

## 5. 下划线和跟随操作条

- 下划线完全使用目标应用的 marked-text 绘制，跟随自身排版、换行和滚动；不再计算每个字的屏幕矩形或绘制透明 Canvas。
- 操作条使用组件内的 AppKit 非激活 `NSPanel`，状态与按钮由同一个事务驱动；点击按钮保持目标输入会话和光标焦点。
- 通过输入法客户端提供的插入位置／字符矩形定位。优先在当前组合末端的下方显示，屏幕底部不足时翻到上方，并处理多显示器、缩放、窗口移动和换行。
- 编辑过程中保留状态和取消；所有按钮的标签随阶段变化，无候选词列表、整段转写预览或第二个底部浮窗。
- `IMKCandidates` 可作原生位置行为参考，但其候选词列表不能直接等价为自定义“撤销／转换”按钮；操作条仍需实现和实测。
- 有效期间按更新事件刷新坐标，并用轻量几何刷新补足滚动／窗口移动；不反复拉全文，不逐字跨进程通信。坐标不可靠时暂停跟随展示，不在旧位置假装成功。

## 6. 与系统拼音共存：已确认手动切换

普通 keyboard input method 在同一时刻只能选中一个。选中本组件时，系统拼音不会同时接收键盘输入；把按键原样传递给目标应用也不等于转交系统拼音。

用户已选择：**手动选中 ProxiMic 语音；需要拼音时手动切回。** 程序和安装器不自动选择或恢复任何输入法，不开发并行拼音引擎，也不把 Palette 输入法列入此次实现。

只要组件仍处于当前输入会话，浮窗隐藏后有效事务仍支持手势操作。用户切回拼音就结束当前事务，后续识别／模型结果不会再写入。

公开 IMK 客户端接口能恢复被选中文字，但不提供通用的已定稿选区设置接口。因此撤销保证恢复文字，通常光标落在恢复文字末尾；不为复原选区高亮引入 AX 或模拟按键，也不残留假组合。

## 8. 安装与异常恢复

- 构建独立 `.app`，开发验证先使用本地签名，正式分发配置正式签名和公证。
- 安装到当前用户 `~/Library/Input Methods/`，注册后引导启用；检查是否真正列出、选中并收到客户端连接，不以复制文件成功代替安装成功。
- 主程序检查组件版本、连接与活动状态；卸载前由用户手动切回其他输入法并退出组件，再移除本产品安装文件。安装、更新和卸载均不自动切换输入源。
- 主程序断连／ASR 出错：当前可见 partial 按客户端生命周期尽可能定稿保留，停止后续写入并提示；不把失败当作空 final 清空内容。
- 模型失败：从 B 恢复 D，显示失败状态，仍可撤销；若要再编辑，开始新句口述指令。
- 组件崩溃时未定稿文字的最终处置受目标应用影响，不能承诺完全恢复；测试进程退出与重连，旧连接的消息一律无效。

## 9. 实施顺序和验收

1. **原生能力样机。** 构建可注册的小组件，通过模拟 ASR 验证真实 Codex／微信的 marked text、全文读取、指定范围替换、焦点行为和非激活操作条；先明确三个独立能力是否可用。
2. **完整事务。** 实现表中全部流程与快照恢复，加入 UTF-16／emoji／中文多行、重复消息、取消竞态和手动接管验证。
3. **主程序接入。** 接真实 ASR、现有手势事件、模型 worker、context 和状态显示；不重测戒指识别准确率。模拟事件与真实手势走同一命令入口。
4. **清理迁移。** 删除非组件路径、旧体验入口和无关 AX 测试，更新用户安装／使用文档，检查无隐藏 AX context 依赖。
5. **真实验收。** 两个应用分别完成下表；以真实结果为准，不能以自制文本框或单元测试通过替代。

| 场景 | 合格表现 |
| --- | --- |
| 空白框和已有正文 | partial 原位修订，无提示占位文字混入、无重复、无丢失原文 |
| 中间光标和选区替换 | 插入位置正确；撤销恢复原文，光标位于恢复文字末尾 |
| 多行、emoji、滚动、窗口移动 | 原生下划线正确；操作条不抢焦点、跟随且不出屏 |
| 正常结束 | 只定稿一次，final 与 ASR 一致，没有发消息 |
| 下划线期间转编辑／定稿后拒绝转换 | 指令只作用于可验证的句前原文；结果到达才撤掉指令并直接应用 |
| 等 final、等模型、已应用三个阶段取消 | 分别回到已约定的听写状态，迟到结果不再次写入 |
| 浮窗隐藏后手势撤销 | 事务有效时仍可执行；新句／手动接管后不能改旧句 |
| 打字、移动光标、换框、换输入法 | 用户操作优先，旧句立即失效，结果不进入新框 |
| 断网、模型失败、组件断连重连 | 无空文本覆盖、无跨句／跨会话补写 |

记录 partial 收到→提交客户端调用、final→定稿、点击／手势→状态变化的延迟，结合真实操作条录屏检查抖动和焦点。先量测再设性能门槛，不把尚未测得的延迟当成已实现保证。

Codex 的工具禁止自动操作 Codex 自身，所以真实 Codex 验收仍由用户启动体验并操作目标输入框；自动化可完成组件测试、模拟客户端和日志核对，不能绕过该限制。微信验收使用文件传输助手草稿，不发送消息。
