# ProxiMic Voice 客户界面

桌面应用采用 PySide6 + Qt Quick/QML。CLI 继续用于调试和实验，UI 直接调用同一套
Ring、ProxiMic、ASR、按住说话和文本注入模块，不启动或解析额外的终端进程。

## 安装

标准用户优先运行项目脚本。Windows 安装会询问使用 CPU 还是 NVIDIA GPU；macOS
使用 Apple Silicon CPU 路径：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

Windows 标准安装会同时把固定版本的 llama.cpp 和默认 Qwen GGUF 下载到
`.runtime/local-llm/` 并进行 SHA-256 校验，不要求用户另外安装 Ollama 或手动寻找模型。
该目录不属于 Python 虚拟环境；设置 `PROXIMIC_LLM_HOME` 后可整体放到其他磁盘。

```bash
./scripts/setup-macos.sh
```

在已经激活的项目环境中安装 UI 和运行依赖：

```powershell
python -m pip install -e ".[ring,asr-streaming-sensevoice,asr-funasr-nano,asr-volcengine,ui]"
```

## 启动

```powershell
proximic-ring-ui
```

也可以从源码入口启动：

```powershell
python -m proximic_ring.ui
```

首次启动时检查以下设置：

- ProxiMic 模型路径和 Stage1 threshold，当前训练模型建议从 `0.005` 开始。
- Ring 音频编码默认选择 PCM，以匹配近点模型训练和阈值校准使用的波形分布。
- ASR 后端、模型和运行设备。
- `streaming-sensevoice` 默认使用 `third_party/streaming-sensevoice` 源码快照。
- 选择 `funasr_nano` 时默认使用 `third_party/Fun-ASR`；目录必须包含 `model.py`。ASR 模型
  留空时会优先使用 `pretrained_models/Fun-ASR-Nano-2512` 本地 checkpoint。
- `funasr_nano` 的“识别热词”支持每行一个，也支持中文/英文逗号和分号；保存时会自动
  去除空项和重复项，重新连接设备后使用新的热词列表。
- 是否启用跨应用文本注入和右 `Alt` 按住说话。
- 文本大模型来源可选“本地 GGUF”或“火山方舟（在线）”。本地模式配置 llama-server、
  GGUF 路径；线上模式可选豆包 Seed 2.0 Lite 或 DeepSeek V4 Flash，并配置方舟 Base URL、
  模型 ID 和“线上大模型 API Key”。选择在线 `volcengine` ASR 时还会显示独立的
  “线上语音模型 API Key”；两者都可直接填写、显示/隐藏、修改或清除。

运行设备使用下拉框展示 CPU 和 PyTorch 当前可用的 NVIDIA GPU。Windows 已检测到
NVIDIA 显卡、但环境仍是 CPU 版 PyTorch 时，可以点击“安装 NVIDIA GPU 加速”；应用
会先退出，再由独立脚本替换运行库并验证，成功后自动重启。macOS 不显示该按钮，当前
保持使用 CPU。火山引擎是云端 ASR，不使用本机运行设备。

先点击“选择并连接设备”，应用会持续发现附近 BLE 设备。搜索框默认填写 `Ringo`，
可以修改关键词或清空以查看全部设备；该关键词只筛选显示结果，不会改变底层扫描范围。
设备按首次发现顺序稳定显示，新设备追加到末尾，不会因信号强度变化反复重排。在列表中
确认名称和设备标识后，点击对应项连接；程序不会自动选择或连接任何设备。
点击后，Windows 会在实际 BLE 运行线程内按所选地址重新定位一次设备，保证扫描、连接和通知
处于同一个 asyncio/WinRT MTA 线程。已知 MAC 地址时发现目标便立即结束扫描，最长等待 3 秒，
后续 BLE 连接握手仍保留原超时；macOS 则保留列表中的 CoreBluetooth 扫描对象。
连接流程依次显示“正在连接设备”“正在加载检测模型”“正在加载语音模型”
“正在启动并确认实时音频”和“准备就绪”。应用先保持 MIC 关闭并完成耗时模型加载，
再一次性开启音频流并验证真实 PCM。设备连接后，“开启/暂停语音识别”只
控制检测与 ASR，不会断开 Ring；需要释放设备时单独点击“断开设备”。设备保持连接时
设置会暂时锁定，断开后可以修改。

首次连接在模型加载期间保持 MIC 关闭，避免模型初始化阻塞 Windows BLE 通知回调；模型完成
后开启 MIC，收到真实 PCM 才进入准备状态。ADPCM 会由 SDK 解码
成 16 kHz PCM，但有损压缩仍可能改变 Stage2 分数分布。Windows 安装脚本会把 Opus
1.6.1 运行库放入项目 `.runtime/opus`，并安装 `opuslib`；已有环境可单独运行
`scripts/install-opus-runtime.ps1`，然后安装 `.[ring-opus]`。

音频流短暂停顿时，stream monitor 会打印底层收包诊断但保留仍然在线的 BLE 会话，等待音频
自行恢复，不再因为 watchdog 主动断链并制造 WinError 995/1223。若长时间没有恢复，用户可
点击“断开设备”后再使用“重新连接设备”；也可以点击“选择其他设备”更换目标。若启动阶段
只收到不超过 5 个 PCM callback 后停流，程序会在 2 秒后只执行一次 MIC OFF / MIC ON 恢复，
避免固件随后主动断开 BLE，同时不会无限循环重启麦克风。
主动断开时会先停止接收识别任务并释放设备，尚未完成的当前语句不会被提交为最终文本。
设备状态与后台初始化状态相互独立：蓝牙和麦克风释放后立即显示“设备已断开”；如果
Fun-ASR/PyTorch 正在完成不可中断的底层加载调用，界面会同时说明后台初始化仍在结束。
连接、NUS 服务或首次真实 PCM 验证失败时应用会自动关闭设备，无需用户再次点击断开。

首次成功验证设备后，应用加载并保留最近使用的 ASR 模型。之后在同一次应用运行中断开、
重新连接相同配置时会直接复用内存模型，不重复构建 Fun-ASR 或加载 `model.pt`。更改后端、
模型、语言、CPU/GPU 或完全退出应用会使该内存复用失效；模型文件的磁盘缓存不会因此删除。

主界面提供“输入到光标”和“修改当前文本”。全局快捷键分别是 `Alt+1` 与
`Alt+2`，右 `Alt` 负责按住说话。当前模式和目标文本框在一句语音第一次
产生识别更新时锁定，途中切换只影响下一句。后续 Ring 手势只需发送相同的 input、edit、
confirm、cancel、retry 以及三个失败原因动作，无需修改 ASR、大模型或桌面适配层。

ASR final 始终进入独立文本处理线程。选择本地模式时，应用首帧显示后即在后台启动安装阶段
准备的 `llama-server.exe`、加载 GGUF，并用极短请求分别预热输入和修改提示词；后续请求
复用服务和 prompt cache，应用退出时释放由应用启动的进程，不需要 API Key。选择火山方舟
时，应用使用方舟 `/responses` 接口，可选择豆包 Lite 或 DeepSeek V4 Flash，并优先使用
设置页保存的线上大模型 Key。线上语音模型使用单独保存的豆包语音 App Key；两个密码框都
保存到当前操作系统用户的 Qt 应用设置，环境变量只作旧版兼容兜底。听写提示词负责去除口语填充、纠错和
断句，但不回答或执行口述内容。修改提示词接收“当前文本框全文 + 修改要求”：删除、替换和
插入只返回短 JSON 操作计划并由 Python 执行；润色、翻译、扩写、重排和格式重组才返回全文。

本地模型包由 JSON 清单描述，运行层只接收模型路径、模型别名和启动参数，对具体 Qwen
型号没有依赖。更换其他 GGUF 或连接其他 OpenAI-compatible 本地服务时，文本处理 worker、
输入/修改状态机和 ASR 链路保持不变。

输入模式的最终处理结果会注入说话开始时锁定的外部文本框。修改模式不会立即覆盖：悬浮窗
只显示本次识别到的修改指令，`Enter` 确认、`Esc` 取消、再次按住右 `Alt` 重说指令。
确认后回到已锁定的目标文本框并整段替换；窗口已关闭或焦点控件失效时停止覆盖。
临时读取使用 Select-All/Copy，但 Qt 会保存并恢复剪贴板 MIME 内容。
主窗口只读记录 ASR、LLM 结果、目标和应用状态，不再作为文本真源或第二个编辑器。

如果两条 LLM 编辑分支都失败、返回空结果，或返回的候选与原文相同，悬浮窗会持续显示
具体错误且不再提供“确认应用”，只保留“重说指令”和“取消”。重说会复用同一目标文本，
在同一 Episode 创建新 Attempt；已失败 Attempt 的原因自动标记为 `llm_error`，无需用户
再按失败原因快捷键。任一分支先产生有效候选时会立即显示；另一分支只在后台完成数据采集，
不会阻塞预览和后续用户操作。

重说或取消后，转写浮窗右侧会出现 10 秒的小型失败原因提示。当前临时快捷键为
`Alt+A`（语音识别错误）、`Alt+L`（大模型理解错误）和 `Alt+O`（其他原因）；这些键只在
原因提示有效期间被全局拦截。超时或先执行下一次确认、取消、重说时，上一 Attempt 保持未标注。
连续重说或取消产生新提示时，旧提示会先关闭 180 ms 再显示新提示，并从重新显示时开始
计算完整 10 秒，避免两个相同提示在视觉上连成一个没有更新的浮窗。短暂刷新期间的数据
绑定已经切换到最新 Attempt，不会把选择写回上一条失败记录。

关闭主窗口会退出程序并释放设备，不再隐藏为不可见的后台进程。终端中的 `Ctrl+C` 也
会触发同一退出流程；若设备清理异常，最多等待约 5 秒。

## 当前范围

- 已有：设备/识别分离控制、模型配置、状态展示、跨应用实时字幕、会话记录、日志、系统
  托盘、配置持久化、桌面输入、按住说话、输入/修改双模式、修改确认流程和异步本地模型处理。
- 尚未加入：文件选择器、可编辑快捷键、自动升级、安装包和 Ring 手势动作映射。

配置通过 Qt `QSettings` 保存。QML 只负责展示和用户交互；识别链路继续运行在后台
Python 线程，所有 UI 更新通过 Qt queued signal 回到主线程。
