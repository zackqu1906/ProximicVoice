# ProxiMic Voice 客户界面

桌面应用采用 PySide6 + Qt Quick/QML。CLI 继续用于调试和实验，UI 直接调用同一套
Ring、ProxiMic、ASR、按住说话和文本注入模块，不启动或解析额外的终端进程。

## 安装

标准用户优先运行项目脚本。Windows 安装会询问使用 CPU 还是 NVIDIA GPU；macOS
使用 Apple Silicon CPU 路径：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

Windows 标准安装会同时把固定版本的 llama.cpp 和默认 Qwen GGUF 下载到
`.runtime/local-llm/` 并进行 SHA-256 校验，不要求用户另外安装 Ollama 或手动寻找模型。
该目录不属于 Python 虚拟环境；设置 `PROXIMIC_LLM_HOME` 后可整体放到其他磁盘。

```bash
./scripts/setup-macos.sh
```

在已经激活的项目环境中安装 UI 和运行依赖：

```powershell
python -m pip install -e ".[ring,asr-streaming-sensevoice,asr-funasr-nano,asr-volcengine,ui]"
```

## 启动

```powershell
proximic-ring-ui
```

也可以从源码入口启动：

```powershell
python -m proximic_ring.ui
```

Ring 非主动断开时，会在当前使用的屏幕弹出独立置顶提示；主窗口在后台或隐藏时也会显示，
提示保留到用户点击“知道了”或重新连接。语音、手势和待处理的文本任务会立即停止，迟到的
识别结果不会继续写入文本框；通知先于蓝牙和模型清理发出。同一次断连只提示一次，主动
点击断开或退出应用时不弹窗，暂停识别也不算断连。重新连接后需手动开启语音识别。

首次启动时检查以下设置：

- “语音启停方式”与“音频来源”独立保存，可组成四种组合，默认仍为 Ring 音频＋靠近说话开始。
  - 靠近说话：保留原流程，近点模型开始识别，确认手势结束本句。
  - 纯手势：不加载、不运行近点模型；开启语音识别后，确认手势开始，再做一次结束。
    使用设置中的确认手势（默认 tap），上一句处理期间的开始手势会忽略，处理完成后需再次做手势。
  - Ring 麦克风：保留原音频路径。电脑麦克风（DJI）：自动识别唯一 DJI 输入，也可在下拉框
    明确指定输入设备并刷新。设备丢失时不会切到系统默认麦克风；重插后按设备名称和音频接口重新定位。
    系统可直接提供 16 kHz 时原样使用，否则按设备原生采样率采集，再连续重采样为单声道 16 kHz。
  - DJI＋靠近说话时，近点检测与 ASR 都使用 DJI 音频。既有模型在 DJI 上的触发效果需要实测。
    DJI 模式下 Ring 只开启 IMU 手势，不开启 Ring MIC；四种组合都需要 Ring 保持连接。
    Ring 或电脑麦克风意外断开时停止交互并弹窗；主动断开不弹窗。
  - 两个模式及输入设备需断开连接后修改；确认手势仍可即时调整。纯手势模式不启用右 Alt 按住说话。
    macOS 首次使用 DJI 需允许应用访问麦克风。历史记录标明音频来源和启停方式，纯手势不产生近点训练标签。
- ProxiMic 模型路径和 Stage1 threshold，当前训练模型建议从 `0.005` 开始。
- Ring 音频编码默认选择 PCM，以匹配近点模型训练和阈值校准使用的波形分布。
- ASR 后端、模型、运行设备和 0 至 +12 dB 输入增益；增益在近点模型之后应用，语音记录保存同一增强波形。
- `streaming-sensevoice` 默认使用 `third_party/streaming-sensevoice` 源码快照。
- 选择 `funasr_nano` 时默认使用 `third_party/Fun-ASR`；目录必须包含 `model.py`。ASR 模型
  留空时会优先使用 `pretrained_models/Fun-ASR-Nano-2512` 本地 checkpoint。
- `funasr_nano` 的“识别热词”支持每行一个，也支持中文/英文逗号和分号；保存时会自动
  去除空项和重复项，重新连接设备后使用新的热词列表。
- 是否启用跨应用文本注入和右 `Alt` 按住说话。
- “手势操作”可为确认、撤销、转换分别设置最多两个手势，禁止重复分配；默认 tap 确认，
  左/下滑撤销，右/上滑转换。确认在靠近说话模式下结束本句，在纯手势模式下开始／结束本句，
  至少保留一个手势；撤销在处理中用于取消。
  修改即时生效并自动保存，不改变按键功能，也可一键恢复默认。
- 文本大模型来源可选“本地 GGUF”或“火山方舟（在线）”。本地模式配置 llama-server、
  GGUF 路径；线上模式可选豆包 Seed 2.0 Lite 或 DeepSeek V4 Flash，并配置方舟 Base URL、
  模型 ID 和“线上大模型 API Key”。选择在线 `volcengine` ASR 时还会显示独立的
  “线上语音模型 API Key”；两者都可直接填写、显示/隐藏、修改或清除。
- 听写／编辑类型判断最多输出 16 tokens；云端听写整理、编辑及编辑重试统一最多输出
  32,768 tokens，本地模型还受已配置的上下文窗口限制。输出上限不会要求模型填满。
  底部浮窗只在等待当前选中的文本 LLM 结果时显示紫色高亮、转圈和“LLM 正在处理文本”。
  语音识别、类型判断、写入结果及后台备用候选不显示该提示。

运行设备使用下拉框展示 CPU 和 PyTorch 当前可用的 NVIDIA GPU。Windows 已检测到
NVIDIA 显卡、但环境仍是 CPU 版 PyTorch 时，可以点击“安装 NVIDIA GPU 加速”；应用
会先退出，再由独立脚本替换运行库并验证，成功后自动重启。macOS 不显示该按钮，当前
保持使用 CPU。火山引擎是云端 ASR，不使用本机运行设备。

先点击“选择并连接设备”，应用会持续发现附近 BLE 设备。搜索框默认填写 `Ringo`，
可以修改关键词或清空以查看全部设备；该关键词只筛选显示结果，不会改变底层扫描范围。
设备按首次发现顺序稳定显示，新设备追加到末尾，不会因信号强度变化反复重排。在列表中
确认名称和设备标识后，点击对应项连接；程序不会自动选择或连接任何设备。
点击后，Windows 会在实际 BLE 运行线程内按所选地址重新定位一次设备，保证扫描、连接和通知
处于同一个 asyncio/WinRT MTA 线程。已知 MAC 地址时发现目标便立即结束扫描，最长等待 3 秒，
后续 BLE 连接握手仍保留原超时；macOS 则保留列表中的 CoreBluetooth 扫描对象。
连接流程依次显示“正在连接设备”“正在加载检测模型”“正在加载语音模型”
“正在启动并确认实时音频”和“准备就绪”。应用先保持 MIC 关闭并完成耗时模型加载，
再一次性开启音频流并验证真实 PCM。设备连接后，“开启/暂停语音识别”只
控制检测与 ASR，不会断开 Ring；需要释放设备时单独点击“断开设备”。设备保持连接时
设置会暂时锁定，断开后可以修改。

首次连接在模型加载期间保持 MIC 关闭，避免模型初始化阻塞 Windows BLE 通知回调；模型完成
后开启 MIC，收到真实 PCM 才进入准备状态。ADPCM 会由 SDK 解码
成 16 kHz PCM，但有损压缩仍可能改变 Stage2 分数分布。Windows 安装脚本会把 Opus
1.6.1 运行库放入项目 `.runtime/opus`，并安装 `opuslib`；已有环境可单独运行
`scripts/install-opus-runtime.ps1`，然后安装 `.[ring-opus]`。

音频流短暂停顿时，stream monitor 会打印底层收包诊断但保留仍然在线的 BLE 会话，等待音频
自行恢复，不再因为 watchdog 主动断链并制造 WinError 995/1223。若长时间没有恢复，用户可
点击“断开设备”后再使用“重新连接设备”；也可以点击“选择其他设备”更换目标。若启动阶段
只收到不超过 5 个 PCM callback 后停流，程序会在 2 秒后只执行一次 MIC OFF / MIC ON 恢复，
避免固件随后主动断开 BLE，同时不会无限循环重启麦克风。
主动断开时会先停止接收识别任务并释放设备，尚未完成的当前语句不会被提交为最终文本。
设备状态与后台初始化状态相互独立：蓝牙和麦克风释放后立即显示“设备已断开”；如果
Fun-ASR/PyTorch 正在完成不可中断的底层加载调用，界面会同时说明后台初始化仍在结束。
连接、NUS 服务或首次真实 PCM 验证失败时应用会自动关闭设备，无需用户再次点击断开。

首次成功验证设备后，应用加载并保留最近使用的 ASR 模型。之后在同一次应用运行中断开、
重新连接相同配置时会直接复用内存模型，不重复构建 Fun-ASR 或加载 `model.pt`。更改后端、
模型、语言、CPU/GPU 或完全退出应用会使该内存复用失效；模型文件的磁盘缓存不会因此删除。

主界面提供“输入到光标”和“修改当前文本”。全局快捷键分别是 `Alt+1` 与
`Alt+2`，右 `Alt` 负责按住说话。当前模式和目标文本框在一句语音第一次
产生识别更新时锁定，途中切换只影响下一句。按钮、快捷键和后续 Ring 手势统一发送
input、edit、cancel、switch_mode、undo 等设备无关动作，无需修改 ASR、大模型或桌面适配层。

设备、识别模型和文本模型配置集中在顶栏“设置”打开的独立窗口中，和实时
日志一样不再占用主界面空间。设备已连接或正在切换状态时设置项保持只读，
避免运行中途改变模型参数。

ASR final 始终进入独立文本处理线程。选择本地模式时，应用首帧显示后即在后台启动安装阶段
准备的 `llama-server.exe`、加载 GGUF，并用极短请求分别预热输入和修改提示词；后续请求
复用服务和 prompt cache，应用退出时释放由应用启动的进程，不需要 API Key。选择火山方舟
时，应用使用方舟 `/responses` 接口，可选择豆包 Lite 或 DeepSeek V4 Flash，并优先使用
设置页保存的线上大模型 Key。线上语音模型使用单独保存的豆包语音 App Key；两个密码框都
保存到当前操作系统用户的 Qt 应用设置，环境变量只作旧版兼容兜底。听写提示词负责去除口语填充、纠错和
断句，但不回答或执行口述内容。修改提示词接收“当前文本框全文 + 修改要求”，先区分整体
编辑与局部修改。“润色一下”本身就是完整指令，未指定范围时处理全文，不要求先找到错词。
整体编辑可调整措辞、语序、断句；除用户明确要求更改的信息外，保留事实、否定、不确定性
与时间关系，不补造背景。局部修改只改指定目标，其余字词、空格和标点逐字保留。
片段替换与全文返回两种协议共用这些规则；片段协议在整体编辑时也可以覆盖全文。
对于单独、明确的全文字数指令，如“扩写到100个字”或“扩写到一百字”，候选必须比原文长，
且非空白字符数在目标的90%～110%内（包含标点）。两路各自先校验，再选首个合格结果；
两路都不合格时提示失败，不写入。该本地检查不增加双协议请求次数，也不判断事实是否正确。
“大约”、指定某一段及复合指令目前仍由模型处理，不套用上述整体字数检查。
提示词对比、真实失败案例重放与已知限制见
`../experiments/llm_edit_prompt_comparison_20260917/README.md`。

自动分类和编辑提示词支持口述纠错：例如“街道的街面包的面”可将唯一对应的“界面”改成
“街面”；“不是晴天的晴，是清水的清”取肯定的字；英文可说“那个词拼作 n u m p y，
全小写”。可明确指定首字母大写、下划线等。释字说明不会作为正文插入；只做目标替换，
不顺便润色。目标有多个、范围不明时要求保留原文，可补说“最后一个”或“全部”。
转述、教学、自我介绍或明确要求输入这些说明仍按听写处理。这些行为由 LLM 提示词约束，
实际效果也依赖 ASR 转写；多候选选择尚未接入，研究见 `LLM_EDIT_CANDIDATES_RESEARCH.md`。

本地模型包由 JSON 清单描述，运行层只接收模型路径、模型别名和启动参数，对具体 Qwen
型号没有依赖。更换其他 GGUF 或连接其他 OpenAI-compatible 本地服务时，文本处理 worker、
输入/修改状态机和 ASR 链路保持不变。

听写和修改的有效结果都会直接应用到说话开始时锁定的外部文本框；窗口已关闭或焦点控件
失效时停止写入。屏幕底部显示“正在收听语音 / 正在处理语音 / 正在处理文本”、实时识别
文字和取消按钮。识别文字自动换行，浮窗保持底边固定，以 180 ms 动画向上展开或收起，
按钮固定在底部。高度最多占屏幕可用高度的 70%；更长的内容完整保留，可滚动查看。
滚动到最新内容时自动跟随识别更新，向上回看时保持阅读位置。
临时读取使用 Select-All/Copy，但 Qt 会保存并恢复剪贴板 MIME 内容。
主窗口按句保存最终裁剪录音和 ASR 文字，支持播放并在重启后保留。
听写或修改应用成功后，底部状态窗关闭，输入完成后的光标右上侧出现轻量操作条，显示
“撤销”和“改用编辑指令/改用听写内容”。按钮下方同时显示键盘快捷键与当前配置的手势，
例如 `Esc · 左滑/下滑`、`F8 · 右滑/上滑`；修改设置后同步更新，未分配手势时只显示快捷键。
定位优先使用真实文字光标，读不到时使用输入框边界；两者都不可用时放在当前屏幕下方中央。
鼠标位置只用于选择兜底显示屏，不充当文字光标。定位保留多屏原点和负坐标，限制在屏幕可用区域内，避开 Dock、菜单栏和任务栏。
操作条默认比原来上移 24 像素，也可手动拖动。处理中 `Esc` 表示取消，应用后 `Esc` 表示撤销；操作条避开已取得坐标的文本框，目标应用退到后台时
操作条一起隐藏，回到目标后可以恢复。原生撤销可连续触发，不受内部操作记录数量或
操作条超时隐藏限制；记录耗尽后点回原文本框仍可重试，断开设备会清除保留的撤销目标。
用于发现用户手写结果的后台观察只允许使用 macOS Accessibility 或 Windows UI Automation
直接读取控件值，不会激活窗口、全选文本、复制、改变选区或移动光标。目标应用不支持安全读取
时跳过自动手写关联，用户仍可在数据关联中心手动建立关联。

如果两条 LLM 编辑分支都失败、返回空结果，或返回的候选与原文相同，底部状态窗会短暂显示
修改未完成，原文本保持不变。系统不会再询问取消或撤回原因。
任一分支先产生有效候选时会立即显示；另一分支只在后台完成数据采集，
不会阻塞应用和后续用户操作。

语音记录中的“编辑指令”表示本句话的类型。修改结果及“已修改”摘要只在最终状态为
已应用或已确认时显示；模型已返回候选不等于文本框已修改。处理或写入失败时，记录显示
“修改未完成”，不展示候选为成功结果；取消显示“已取消”。失败反馈会立即刷新列表。
原始模型返回、失败原因和候选仍保存在交互记录中，供数据关联和排查使用。
旧记录重新加载时也遵循这一展示规则，无需改写历史数据。

若开启“智能推荐关联”，一次成功听写或编辑会将上次成功之后、同一目标文本框中的最近
失败记录作为推荐反例。推荐浮窗只显示摘要；详情窗用绿色标记正例、红色标记反例。
智能推荐默认关闭。启用后，推荐在结果应用时立即出现，并优先放在目标文本框旁边、操作条的
另一侧；无法取得控件坐标时放在屏幕右上方。点击“关联”会立即确认本次成功结果并关闭撤回
能力。
主界面的“数据关联中心”也可手动建立 ASR 或 LLM 关联。
进入关联中心后，需要先点击“创建一次关联”，再选择类型、一个正例和一个或多个反例。
确认页会完整展示本组内容；只有点击“确定创建”才会生成一个 `association_id`，返回修改或
直接关闭窗口都不会保存草稿。

关闭主窗口会退出程序并释放设备，不再隐藏为不可见的后台进程。终端中的 `Ctrl+C` 也
会触发同一退出流程；若设备清理异常，最多等待约 5 秒。

## 当前范围

- 已有：设备/识别分离控制、模型配置、状态展示、跨应用状态浮窗、会话记录、日志、系统
  托盘、配置持久化、桌面输入、按住说话、输入/修改双模式、操作栈撤销和异步本地模型处理。
- 尚未加入：文件选择器、可编辑快捷键、自动升级、安装包和 Ring 手势动作映射。

配置通过 Qt `QSettings` 保存。QML 只负责展示和用户交互；识别链路继续运行在后台
Python 线程，所有 UI 更新通过 Qt queued signal 回到主线程。
