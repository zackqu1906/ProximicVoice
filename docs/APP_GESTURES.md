# macOS 应用手势

本功能根据前台应用选择一组原生快捷键。支持 Codex、WorkBuddy 和微信；不包含 Codex 项目选择器。仅更新源码，不需要更新输入法组件，也不构建 DMG。

## 默认分配

| 手势 | Codex | WorkBuddy | 微信 |
| --- | --- | --- | --- |
| 上滑 | 发送：Return | 发送：Return | 发送：Return |
| 逆时针画圈 | 上一个任务/标签：Cmd+Shift+[ | 上一个任务：Cmd+[ | 上一个聊天：建议分配 Cmd+Shift+[ |
| 顺时针画圈 | 下一个任务/标签：Cmd+Shift+] | 下一个任务：Cmd+] | 下一个聊天：建议分配 Cmd+Shift+] |
| 食指捏合 | 新建任务：Cmd+N | 新建任务：Cmd+N | 不分配 |

Tap 开始/结束听写、左滑取消/撤销、右滑将仍有下划线的本句转为编辑，继续走语音逻辑。旧版本附带的“下滑撤销、上滑转编辑”别名自动移除；用户自行修改过的分配保留。新安装默认以手势开始/结束听写，已有的近场模式选择保留。

快捷键效果服从目标应用当前的原生行为。例如 Codex 上下切换可能切换任务或标签；发送键被用户在目标应用中改过时，需在 ProxiMic 同步调整。系统或应用的搜索框、菜单和可识别的弹窗不接收这些手势。

## 生效阶段

| 阶段 | 上滑发送 | 画圈切换 / 捏合新建 |
| --- | --- | --- |
| 空闲、定稿完成、编辑应用完成、撤销完成 | 立即发出一次发送快捷键 | 立即发出一次对应快捷键 |
| 正在开始听写、听写中、等待本句定稿 | 请求结束本句；真实 ASR 定稿并写入成功后发送一次 | 不执行、不排队；提示先结束听写 |
| 已转换为编辑、等待大模型、正在应用或撤销文本 | 不执行，给出短提示 | 不执行，给出短提示 |
| 取消、空句、定稿失败、等待超时、连接/目标/设置发生变化 | 取消先前等待的发送，需重新触发 | 不补发以前的手势 |

设备需要保持连接并开启手势识别；暂停语音识别或切换到其他输入法，不影响空闲阶段的应用操作。发送时应将焦点放在消息输入框。听写中发送会固定到当时的应用、进程、窗口、输入控件和语音句子，最长等定稿 12 秒。短时间重复触发不会重复发送。

同一个手势可以跨应用复用，也可与左滑/右滑等语音动作复用：当前存在对应取消、撤销或转换动作时，优先执行语音动作。开始/结束听写手势独立保留。同一应用内同时生效的应用动作不能重复分配。

发送或切换对话后，当前文本操作和撤销记录结束，不会继续把上一对话的撤销应用到新对话。完成态的主机记录会立即释放，忽略旧输入法回调，不影响下一句。

## 设置与微信配置

打开“设置 → 手势与快捷键 → 发送与切换对话”，选择应用，可修改每项手势、键位和启用状态。点击快捷键框即进入录制，直接按组合键保存；Esc 取消，离开输入框、返回上一层或切到其他应用时停止录制。不再需要点击单独的“录制”按钮。修饰键单独按下不会保存，Shift／Option 改变字符时仍按对应物理键记录。这里配置的是 ProxiMic 发出的按键，不会改变目标应用自己的键位。

设置首页按“听写与撤销、手势与快捷键、麦克风与启停、语音识别、编辑模型、输入法与权限”分类。每页独立显示相关选项，返回按钮逐层返回；底部“完成”结束设置，修改自动保存。微信的详细填写说明位于“微信聊天切换 · 查看设置步骤”，不占用其他应用的设置页面。

微信没有采用已被用户验证无效的“Cmd+1 后上下键”方案。上一个/下一个聊天需要先配置 macOS App 快捷键：

1. 点击“打开 App 快捷键设置”。程序打开系统键盘设置，再定位到“键盘快捷键 → App 快捷键”，读取选中状态确认成功；不会修改任何系统选项。如果当前系统不允许定位，界面提供同一路径供手动进入。“功能键”开关与微信切换聊天无关，无需为此开启。
2. 设置页默认自动读取正在运行的微信版本和实际菜单语言，为“上一个聊天”“下一个聊天”分别列出系统对话框的三项填写内容：应用程序、菜单标题、键盘快捷键。菜单标题决定执行什么操作，必须原样填写，不能自行起名。只读取菜单，不读取聊天内容，也不根据 macOS 语言猜测。点击“＋”，应用选择微信 / Weixin，使用“复制菜单标题”粘贴准确标题。无法读取时可先展开微信的“显示 / Show”菜单再点“重新识别”，或手动选择简体、繁体、英文菜单名称。相同版本的微信也可能使用不同界面语言。
3. 点击系统的“键盘快捷键”输入框，按下填写说明中的组合键并保存。说明跟随用户当前设置的键位更新，不固定为默认键位。
4. 两项保存后即可回到微信使用画圈切换；没有测试按钮，也不需要勾选确认。旧版本未确认的状态不再阻止手势发出。更改微信切换键或菜单语言后，需同步更新系统配置；微信发送无需此配置。听写、编辑或撤销处理期间仍不切换聊天。

应用按键注入需要 macOS 辅助功能权限；源码运行时权限属于启动 Python 的应用/终端。应用快捷键不自动修改系统设置或处理授权弹窗。输入法切换是下述独立的显式手势动作。

## 验证范围

自动化覆盖阶段判断、识别时与执行时状态不一致、断连/窗口变化、发送去重、空句/错误、复用优先级、设置保存、微信无需测试确认即可发出当前配置的按键，以及使用模拟 macOS API 验证键码、修饰键、目标 PID 和成对按下/松开。QML 测试使用鼠标点击快捷键框后发送 Qt 键盘事件，验证默认录制、快捷键抢占、取消、非法字符、原生键码和退出录制；同时检查分类导航、小窗口布局和随语言及键位更新的微信填写说明。

自动化测试不会向真实 Codex、WorkBuddy 或微信发送消息。真实客户端快捷键效果还需在测试对话中验收；系统或客户端修改默认快捷键时可在设置调整。

## 手势切入语音输入法

单独切换输入法的功能保留，**默认关闭、未绑定手势**。用户在设置中绑定后，采用 macOS `TISSelectInputSource` 直接选中 ProxiMic Voice。此操作只切换，不开始听写；tap 自动切换并开始听写是独立路径。启动和安装程序不会主动选中输入法。

- 设备已连接、手势模型运行时生效；语音识别可以暂停，不限 Codex、微信等应用。
- 切换不受开始听写、听写中、等待定稿、编辑、写入或准备发送等缓存状态限制。输入法实际激活／失活由系统生命周期处理，不因旧状态提示“先完成本句”。
- 只切换输入法，不开启语音、不输入或发送文字；切换后按现有确认手势开始本句。已选中时不重复选择。
- 设置 → 手势与快捷键 → 切入 ProxiMic Voice：可以更换或关闭；只允许未被听写和应用操作占用的手势。已保存的有效绑定继续保留；未配置时不自动分配任何手势。
- 前台应用变化、过期识别事件、断连、快捷键录制期间不切换；组件未安装／未启用时显示具体提示，不自动安装或更改系统授权。
- 切回拼音仍使用系统输入法菜单或系统切换快捷键。
