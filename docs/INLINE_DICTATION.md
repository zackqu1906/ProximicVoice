## 安装与选择

2026-09-19 坐标容错补充：默认原生客户端的定时光标检查不再凭单次读数差异立即中断。暂时的旧坐标、无效选区或 marked range 回退进入只读重试，期间合并最新 partial，恢复后继续；正常一致读数没有固定等待。实时组合写入／归属确认的异常重试上限为 1 秒，定稿编辑／撤销的校验策略不变。明确鼠标、键盘和焦点事件仍立即清除后续工作；持续无法确认归属时结束本句，不重放写入。171 项原生回归及实际 Swift/Python IPC 通过，覆盖模拟 750ms 延迟恢复、零等待正常路径、单次写入、迟到结果不能复活及原有编辑撤销。本机组件已更新，真实跨应用语音体验仍需验收；DMG 未更新。

1. DMG 用户：将 app 拖入“应用程序”，打开主程序，点击“输入法设置”→“安装／更新输入法”，无需 Python 或编译工具。源码用户可用同一界面安装已构建组件，或双击项目根目录 `安装语音输入法.command` 构建并安装。
2. 组件安装在 `~/Library/Input Methods/ProxiMicInput.app`。安装器注册并启用输入源，**不会替你选中输入法**。
3. 连接设备并开启识别后，在可编辑文本框做 **tap**，自动切入 **ProxiMic Voice** 并开始本句；自动切换只检查系统输入法，不依赖辅助功能文本框检测。也可在菜单栏手动切入。单独切换输入法的手势默认未绑定，可在设置 → 手势与快捷键中自行绑定空闲手势；此操作只切换，不开始听写。如未出现，进入系统设置 → 键盘 → 文本输入 → 编辑，添加该输入源；必要时退出登录后再进入。
4. DMG 用户保持 app 运行；源码用户双击 `启动行内听写.command`。连接戒指并配置／开启 ASR，输入框有焦点且组件连接后，主程序会显示已就绪。
5. 需要拼音时手动切回系统拼音。切换会结束当前语音事务，旧识别／编辑结果不能继续写入。

本组件没有自己的键盘拼音引擎。普通键盘输入交还应用；活跃语音事务中的 Esc 取消，转换快捷键沿用主程序设置（默认 F8）。组合中的 Enter 结束本句，不把同一次键继续传成聊天发送。

输入法在 macOS 屏幕右上角菜单栏中选择（图标通常为“A”“拼”或“中”），不是输入框里的按钮。先点入目标输入框，再按住 Control、连续按空格，选到 ProxiMic Voice 后松开；也可直接点菜单项。Control–Option–空格切换至下一种输入法。参见 [Apple 切换输入法说明](https://support.apple.com/zh-cn/guide/mac-help/mchlp1406/mac)。

组件核心输入路径不需要辅助功能权限。微信／Codex 的定稿撤销，以及微信选区替换、Codex 光标定位的兼容层需要主程序有发送原生快捷键的权限，可从“输入法设置”打开辅助功能设置。打包版授权对象为 Proximic Voice，源码终端已有的授权不会自动转给 app。

更新 app 后，需要再次点“安装／更新输入法”，以更新用户目录中的独立组件。先手动切回拼音或 ABC；安装器只正常退出当前用户在本产品安装位置运行的旧组件，不覆盖仍被选中的输入源。校验或注册失败会恢复原组件。全程不自动切换输入法。

## 不连接戒指的真实输入法体验

先退出其他正在运行的源码主程序，避免两个 ASR 主机争用同一输入法连接。

- 双击 `体验行内输入.command`；在准备时间内手动选中 ProxiMic 语音，切到 Codex 普通消息输入框或微信文件传输助手输入框。
- 只模拟 ASR 逐段返回；原生输入法、文字读写、下划线、操作条和撤销均走实际组件。
- 文字会从“今天”逐段修订成“今天下午三点开会，讨论下一阶段的安排。”。
- 用操作条或既有快捷键转换、取消。不会自动选择输入法、点击发送或发送消息；仅微信的定稿撤销／编辑替换会调用原生选区和撤销快捷键。
- 编辑体验：先输入“明天三点开会”，光标置末尾，执行 `./体验行内输入.command --edit --delay 12`。模拟指令是“把三点改成四点。”，只有主动转换时才调用现有模型。
- `.build/input-method/preview.json` 记录状态、字符数和能力，不记录输入框原文。

启动时会立即打印连接状态，等待期间每 5 秒提示当前原因。默认准备时间为 10 秒，之后最多再等 45 秒让目标输入框就绪；起句请求发出后，5 秒内未收到组件确认则停止，不继续模拟文本。修改体验脚本后，需要退出旧体验进程并重新打开 `.command`，无需重新安装输入法。

体验进程约两分半后退出。请在进程仍运行时测试浮窗隐藏后的手势／快捷键操作；退出主程序或切换输入法会终止旧事务。已定稿草稿不会由体验脚本自动清空。

## 交互

每句默认听写。partial 更新本句原生组合，结束后直接采用 ASR final 定稿，不走大模型润色或自动分类。底部识别浮窗继续停用。

开启本句并得到输入法确认后，光标旁操作条立即显示“听写 · 可以说话”，不等待首段识别文字；有文字后显示“听写中”，结束后进入收尾／定稿。只用视觉状态，不播放提示音。没有就绪输入框时不会假装已经开始；主程序显示具体原因，日志 `INPUT_METHOD` / `INPUT_METHOD_CANCEL` 记录会话状态、生命周期和字符数，不新增正文记录。

**本句文字还有下划线时右滑／转换为编辑**：立即结束收音，等待 ASR final，把**说话前的原文**和本次语音指令分别交给模型。等待模型时保留带下划线的指令；模型结果到达后，才撤掉该指令、恢复起句时被替换的选中文字，再直接应用结果。微信在此时全选、读取并核对正文，通过 IME 替换选区。tap 结束并定稿后，不再把该句转换为编辑；操作条只保留撤销。等 final 时取消转换会正常听写定稿；模型处理中取消或失败会把保留的本句定稿为听写；编辑完成后取消也恢复听写，再撤销一次才移除本句。

2026-09-20 编辑等待策略：每条编辑指令只发起一次模型请求。等待期间保留原生未定稿下划线，不发送全选、复制或选区定位快捷键；模型结果返回后才执行原有的原生选区替换。默认兼容客户端在替换时若发现模型使用的原文与实际正文存在实质内容差异，保留听写并提示，不再自动请求第二轮模型。已确认的正文继续用作后续编辑上下文；仍保留最终替换和撤销需要的校验。

2026-09-20 原文边界修复：15:02:23 与 15:04:36 的误报分别比较了 14/12、24/22 个字符；保存的模型输入均在正文末尾多出两个 LF。起句时的 IMK substring 是上下文窗口，不等价于原生全选边界。最终替换以原生选区为准：若模型原文仅在此边界后多出段落换行（LF/CR/段落分隔符），按同一正文处理，不重发模型、不恢复后重新选区。正文中间的换行、空格、字符变化和非零起点范围仍不等价。此规则不修剪真实正文或模型结果；撤销基于原生选区取得的原文，保留用户实际空行。

操作条显示当前状态和必要操作，收尾／等待模型时显示旋转加载图标，模型等待文案为“正在编辑…”。同一输入会话临时读不到光标时保留上次位置，避免等待提示消失；会话结束清除旧位置。等待模型及执行替换时固定操作条位置；替换完成后恢复读取当前光标位置，将结果操作条移到新文本末尾。撤销完成也恢复跟随；坐标短暂不可读时保留最后有效位置并继续读取，不额外等待或修改文本。定稿／应用后默认 5 秒收起。收起后原会话有效时仍可通过手势或快捷键操作。下一句始终重新听写。手动改字、移动光标、换框、换输入法和主机断连都会终止旧句，取消后的迟到结果被丢弃。

撤销恢复被语音替换的原文字。公开 IMK 接口不提供通用的已定稿选区设置方法，因此原来选中文字的高亮不保证复原，光标通常位于恢复文字末尾；不使用 AX 或按键模拟补这个差异。

可以在同一输入框手动往返切换拼音／ABC 与 ProxiMic 语音。切出时终止本句，已上屏且归属明确的组合保留为文字；迟到的 ASR／模型结果不能继续写入。切回时先交接前一输入法的状态，正常无组合时直接就绪。有残留标记时跨主循环观察后，只在能够明确限定替换范围时处理一次：可读文字在原范围原样保留；与当前光标脱离且无法读取的残留候选使用当前光标的显式零长度替换。两者都要求客户端支持文档范围访问。未知的同位组合不清空，不使用默认替换来删除选区，也不通过重放写入强行恢复。

## 技术与兼容边界

输入法通过客户端的 `setMarkedText` / `insertText` 更新文字，通过文档访问接口读取原文与选区。自定义 AppKit 非激活操作条使用输入法提供的光标位置，不逐字绘制下划线。

写入后的回读可能晚于文字实际显示。每次写入只执行一次；确认暂时不一致时，在后续主循环中最多重读 500ms。等待期间合并中间识别结果，保留 final 的顺序；键盘／输入框接管立即丢弃等待任务。超时停止后续写入，不重复写字，也不跳过全文编辑与撤销的内容校验。

三个能力独立验证：原生组合、context 的实际范围、定稿后的范围替换。撤销本句只需校验本句文字、范围及光标，不要求读取全文。编辑使用起句时快照：能读全文时校验全文；客户端只提供带明确范围的原文时，完成后操作条显示“已编辑可读原文”，替换严格限制在该范围，范围外内容保留，`context_complete` 仍为 false。无法校验原文则保留听写并提示编辑未执行，不调用模型；无法校验本句则不盲目撤销。

ASR context 与模型 context 来自输入法。ASR 只使用有界提示，全文编辑保存完整句前快照。Swift 组件持有文本事务；Python 与组件通过用户私有 Unix socket 交换版本化消息，句 ID、会话和 revision 使取消及重连前的结果失效。

当前一次全文快照上限为 512 Ki UTF-16 单元，单句上限为 65536 UTF-16 单元；IPC 消息另有字节上限。过长正文报告能力不可用，不能截成“全文”覆盖。输入法仅涉及当前输入框，不读取已发送的聊天历史。
