2026-09-17，用户要求补测润色以外的任务。本轮固定当前生产提示词，使用已配置的
火山方舟 `deepseek-v4-flash-260425`，完成 **55 个不同场景 + 12 次针对性复测**。
没有调整生产提示词或处理逻辑，也没有执行桌面输入、撤销或写入语音历史。

## 已确认的问题及复测

以下每条共测试三次：首轮一次，提示词不变再测两次。

| 场景 | 观察 |
| --- | --- |
| 听写转述 | **3/3** 把“他说把第二段删掉就可以了。”变成“把第二段删掉就可以了。”；转述关系丢失。这是听写整理结果，不是程序实际执行了删除 |
| 重复目标释字 | **2/3** 把两个“界面”都改成“街面”，**1/3** 正确保持原文；未指定改哪一处，结果有波动 |
| 无新增信息的会议扩写 | **3/3** 新增原文没有的议程、准备材料或参会准备要求；其中一次只有 51 字符，低于本例约 80 字的检查范围 |
| 社区通知扩写 | **2/3** 把“周六开放”改成“每周六开放”，改变了周期；另一次保持周六开放且整体可接受 |
| 进度缩写 | **1/3** 丢掉预计周三开始测试；其余两次保留周三和等待李明确认 |
| 预算缩写 | **3/3** 用“答复时间未定/待定”概括“最快可能周五答复”，保留不确定性，但均删掉周五这一信息 |

复测的原始输出在 `followup_results.json`，未用复测中的成功覆盖首轮失败。

预算缩写的测试要求是“缩成25字以内，保留预算未批和答复时间不确定这两个重点”。
自动检查另外要求出现“周五”，且未将“待定/未定”列入不确定性关键词，口径较严格。
因此该项记为信息保留警告，而不是声称明确指令被违反：模型确实保留了两项明示重点，
但如果产品希望保留原文预计日期，当前输出仍不够。判定差异单独保留，没有篡改原始检查结果。

## 长文本为什么慢

原文第 48 行是“第48条：样品已登记，数量58件，状态待复核。”。
片段分支约 2.36 秒返回时把数量抄成了 **74 件**，使 `original_text` 根本不在原文中，
现有校验正确拒绝了该结果。全文分支约 **10.19 秒** 返回完整且逐字正确的文本，成为胜出分支。

这条测试表明，长文本可能在短片段失败后等待全文生成。本例不是 ASR、焦点读取或桌面写入耗时，
因为这些步骤没有进入测试。只测了一条 1535 字符文本，不能推断所有长文本都需要 10 秒。

## 双协议的限制

两路都通过参数校验，不代表语义正确。生产仍按先取得可执行修改的分支返回，未修改的结果被拒绝。
本轮歧义例中片段分支较快给出“全部替换”，全文分支保持原文；现有流程不会用无变化结果否决另一路。
进度缩写首轮也是片段先返回遗漏日期的结果，较晚的全文分支保留了日期。
这些记录说明“语义正确性”和“工具参数可执行”是两种检查，不能混为一谈。

## 测试方法与适用范围

- `build_cases.py` 生成本轮事先定义的纯合成数据，冻结为 `cases.json`。
- 使用应用保存的模型连接；API Key 只在内存中用于原服务认证，不打印、不保存。
- 编辑的 37 个场景调用生产 `process_with_collection_trace(..., "race")`，保存两种协议的原始输出、
  校验结果和胜出分支。分类的 12 个场景与听写的 6 个场景各调用对应生产入口。
- 分类、听写、编辑分阶段验证，未把 ASR、自动分类、文本框读取和写入串成端到端 UI 测试。
- “识别”作为孤立词按当前分类策略进入听写；已经进入编辑模式时，这个词可以修正“事情”。
  两个测试并不矛盾，也没有证明它在自动分类时会被当作编辑指令。
- 空结果只在明确清空时算有效编辑。两路都明确返回原文的无变化结果，记作现有流程拒绝修改。
  网络故障、格式错误或找不到片段从不算“正确保持原文”。
- 中文字数按非空白字符计，包含标点；“约80字”检查64～96，“约100字”检查80～120，
  明确80～100字故事检查80～100。阈值在测试前定义，没有事后放宽。
- 每次最多运行两个场景，编辑每个场景内部并行两路；诊断等待两路日志收齐。
  `elapsed_s` 通常不是 UI 获得首个结果的延迟，需看胜出分支的 `latency_s`。
- 本轮没有比较其他模型，也没有借本次测试承诺其他模型或未来请求的准确率。
