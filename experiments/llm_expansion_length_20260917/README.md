## 改动

- 缩短扩写提示词，删除“短原文不够指定字数就保持简短”的指令。
- 新增本地 `validate_expansion_result`，匹配独立、明确的全文字数指令，支持100、一百等数值。
- 每个分支在竞速前校验：结果必须比原文长，而且非空白字符数须在目标的90%～110%内，包含标点。
- 两路仍各请求一次，未增加生产竞速模式的重试或额外模型调用。某一路失败时等另一现有分支；
  两路失败则沿用失败流程，不产生可写入候选。
- “约/大约”、局部范围、复合指令不套用此检查，避免误把片段字数当成全文字数。
- 简单入口、同步采集入口、UI异步采集入口均传递独立的指令字段；不从原文标签里猜测指令。

90%～110%是当前实现的容差，不是严格恰好100字；本地检查不验证事实、语义或编辑质量。
它可能使此前错误写入的场景转为失败提示，也可能需要等待较慢但合格的另一分支。
