# 两处短提示词微调

本轮只调整听写转述保护和非虚构扩写规则。生产文件是
`src/proximic_ring/text_processing/prompts.py`；相对本轮开始，听写提示词增加 **26 个字符**，
每份编辑提示词增加 **82 个字符**（共享同一条扩写规则）。没有新增模型请求、验证模型或后处理。

## 当前修改

- 听写：明确“他说、老师让”等不是赘词，必须保留信息来源和转述关系。
- 扩写：限定为依据原文的同义扩述，不用常识补地点、周期、原因、流程、证件或准备要求；
  事实优先于达到字数。用户明确允许虚构时仍可写故事。

只保留以上两个语义改动。旧扩写规则被替换并移至公共编辑提示词末尾，未重复叠加。
分类、缩写、歧义处理和长文本处理逻辑没有修改。

## 验证与限制

使用当前配置的火山方舟 `deepseek-v4-flash-260425`，全是合成例子，复用生产双协议流程。
每份 JSON 保存当时提示词哈希、完整输出和两路记录；不存在覆盖失败后只保留成功的情况。

听写规则从第一次修改到最终版本未再变化：

- 原例“他说把第二段删掉就可以了。”重复 **3 次均保留“他说”**。
- 新例“妈妈说老师让我们明天带上画笔。”和“李明提醒我别忘了给客户回电话。”均保留转述关系。
  前者输出“妈妈告诉我，老师让我们明天带上画笔。”，仍有措辞变化，并非承诺逐字保留所有信息。
- 普通口吃整理、询问句保持正常。相关结果在 `targeted_results.json` 和 `holdout_results.json`。

扩写比较了五种短规则写法。采用 v5，但**尚未稳定解决所有编造，不能宣称修复完成**：

- 最终两次社区图书角案例都保留“周六”，没有改成“每周六”。
- 仍有会议扩写自行加入“资源安排”，独立书画展案例加入“具体开放时段请关注后续通知”，
  并将仅对师生免费扩成仅面向师生。图书馆案例添加了“请择日办理”。
- 这些内容没有充分原文依据，即使工具参数有效或关键词检查通过，也不能算语义正确。
- 最终部分输出比目标字数短，是“事实优先于凑字数”的取舍；短输出本身不能证明没有编造。
- 明确允许虚构的故事扩写仍成功，最终输出符合80～100字检查。

此前各版也发生过新增地点、证件要求、会前准备等问题。为遵守“尽量微改、提示词不要太长”，
本轮没有堆叠长规则或扩大到额外校验逻辑。当前约束会引导模型，但不能保证输出遵守。

代码验证：

```sh

```

结果 **56 passed**；这些测试验证调用、协议和替换，不验证模型的事实正确性。

- `first_attempt_prompts.py.txt` 至 `fourth_attempt_prompts.py.txt`：前四版生产提示词快照。
- `after_prompts.json` / `change.patch`：最终提示词与本轮差异。
- `targeted_results.json`、`holdout_results.json`：第一版结果，听写规则与最终相同。
- `expansion_v2_results.json`：第二版。
- `expansion_v3*_results.json`、`expansion_v4*_results.json`：第三、四版及独立验证。
- `expansion_v5_results.json`、`expansion_v5_holdout_results.json`：最终扩写结果。
